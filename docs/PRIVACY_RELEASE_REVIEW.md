- 공급업체의 국외 처리 중 확인되지 않은 국가·보관 조건 등은 확인 필요 상태로 남긴다. 국내 리전만으로 전체 국내 처리라고 추정하지 않는다.

### 400일 보관의 필요성과 한계

- 현재 재방문율은 가입 후 **7일** 기준이다. 구현되지 않은 장기 재방문 분석을 400일의 근거로 쓰지 않는다.
- 달력 연간·월별 추이와 전년 동월을 비교할 때, 올해 월말까지 전년 같은 달의 첫날을 보유하려면 최대 약 396일(윤년 366일+30일)이 필요하다. 400일은 이 목적을 위한 상한과 작은 운영 여유로 설명할 수 있다. 연간 고유 활동 회원 수는 날짜별 합계를 더해서 대체할 수 없다.
- 구현상 한 번의 사용자 지정 기간은 최대 366일이며, 전년 동월 비교는 각 기간 조회·내보내기를 비교하는 방식이다. 자동 전년 대비 차트나 400일 단일 조회 기능이 있다는 뜻이 아니다.
- 올해 누계·최근 1년만 필요하면 366일, 월간 활성·7일 재방문만 필요하면 더 짧은 기간으로 충분하다. 따라서 400일은 법정 기간이나 유일한 정답이 아니다. 운영팀은 실제 연간·전년 동월 비교 이용 여부를 정기적으로 점검해 유지 근거를 남긴다. 이번에는 400일을 변경하지 않는다.

### ActivityDay 유지 시 필요한 최소 결정

네 기준 공개는 완료되었고, 관련성·제한된 분석 범위·안전조치는 코드로 뒷받침된다. 가장 큰 미확정 부분은 과거 회원에 대한 예측 가능성 및 그에 따른 제15조제3항 적용 판단이다. 운영팀 내 책임자가 이 문서의 기존 안내·위험·보관 목적을 확인하고 기준별 판단과 점검 결과를 기록해야 한다. 불확실한 기존 회원 적용은 이 구체적 사실관계로 법률 전문가에게 확인하며, 유지 의사·공지·HMAC만으로 적법하다고 단정하지 않는다. 이번에는 수집·분석을 중단하거나 동의 구조를 변경하지 않는다.

별도 복구 백업에는 탈퇴·만료 전 데이터가 남을 수 있다. 확인된 주간 백업 4개 보관·검증 후 정리와 사본 잔존 사실을 처리방침 3항에 짧게 반영했다. 수동·배포 전 사본은 자동 삭제에서 제외하고, 보관기간은 향후 별도 운영 기준으로 정한다. 복구 검증과 별개로, 실제 서비스 복원 시 탈퇴·보관 만료 정보를 다시 제공하지 않도록 최신 삭제 상태를 재적용하는 절차도 별도로 운영한다. 현재 해당 기준·자동화가 완료되었다는 뜻은 아니며, 이번에 파일을 삭제하거나 설정을 변경하지 않는다.

## 최근 활동 감지 시각·시간대 분석 (Preview 전용, 미배포)

- **새 처리**: `User.last_active_at` 1개 값(회원별 최근 활동 감지 시각, KST 초 단위 표시). 로그인 상태의 화면 표시·보이는 화면 조작 시 최대 5분 간격(새 시간대는 즉시)으로 덮어쓰며 이력은 남기지 않는다. 관리자 사용자 상세에만 표시하고 회원탈퇴 시 삭제한다. 과거 접속 시각은 추정·소급하지 않는다.
- **집계**: 시간대별 비로그인 페이지뷰(`visit.anon.hour.<HH>`)와 시간대별 활성 회원 수(`active.member.hour.<HH>`, 관리자 제외)를 기존 `MetricDaily` 일괄 쓰기로 추가했다. 회원 정보가 없는 합계이며 회원별 방문 이력 테이블은 만들지 않았다.
- **범위 확대 여부**: 기존 관리자 예외는 최근 이용일(날짜)이었다. 정확한 시각은 같은 이용 기록이지만 더 세밀하므로 처리 범위의 확대로 본다. 동의 화면의 "서비스 이용 기록(로그인 일시, … 이용 내역)"과 처리방침 2항의 회원 관리·부정 이용 방지 목적에 포함된다고 볼 여지는 있으나, 기존 동의자에 대해 이 범위까지 예측 가능했는지는 **확정하지 않았다**. 처리방침 1·3·5항에 항목·보관·표시 범위만 짧게 추가했고, 동의 화면 문구·동의 버전·시행일·개정 이력은 바꾸지 않았다.
