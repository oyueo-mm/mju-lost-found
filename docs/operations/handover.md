# 운영 인수인계

인계자·인수자는 아래 항목을 실제 상태와 대조해 기록합니다. 이 문서는 계정 생성·권한 부여·설치가 이미 완료됐다는 뜻이 아닙니다.

## 접근과 권한

- GitHub 저장소, Vercel 프로젝트, Production/Preview DB·Storage의 관리 주체와 접근 가능 여부를 확인합니다. 비밀값 자체는 문서·CSV·채팅에 옮기지 않고 조직이 사용하는 안전한 비밀 관리 경로로 전달합니다.
- [권한 지침](../ADMIN_PERMISSIONS.md)에 따라 필요한 기능만 부여합니다. QR 생성은 `promotion.manage`, 운영 통계는 `stats.operations`로 구분됩니다. 홍보 권한만으로 통계를 읽을 수 있다고 가정하지 않습니다.
- 개인별 계정을 사용하고 공용 계정이나 실제 계정의 세션 쿠키를 등록부에 공유하지 않습니다. 담당 변경 시 불필요한 권한 회수 여부를 확인합니다.

## QR와 현장

- [등록부](qr-registry.csv)와 [건물 코드](buildings.json)를 인계합니다. 종합관·학생회관·미래관·국제관·행정동·방목학술정보관·MCC 통합 경비실·인문생활관의 8곳, 각 `find`/`reg` 2종입니다.
- 현재 각 QR의 발급 준비·실제 설치·회수 상태를 확인합니다. 세부 위치 미확정이나 설치일 공란을 인계 시 확실히 전달합니다. 설치를 추정해 완료 처리하지 않습니다.
- 과거 guard01~guard08의 실물과 실제 장소 대응 자료가 있으면 기존 기록으로 함께 보관하되, 대응을 모르는데 새 건물 코드로 치환하지 않습니다.
- 최종 인쇄 파일, 실제 QR URL, 버전·용도, 승인된 CSV와 파일 내용 일치 검증, 현장 미결 사항을 전달합니다. 이미 발급된 Content를 다른 장소로 재사용하지 않습니다.

## 통계 읽기

- [UTM 표준](utm-standard.md)의 ‘첫 유입 세션’ 의미와 같은 세션의 QR 재스캔이 새 유입이 아닌 점을 설명합니다.
- 관리자·자동화·통계 제외 설정에 따른 제외를 확인합니다. UI 복귀 성공, 비콘 전송, DB 기록, 통계 표시는 각각 별도 확인합니다.
- Content 측정 전 기간은 미측정이며 기존 source/campaign 데이터와 소급 결합하지 않습니다. 미등록 Content·조합 범주는 등록 누락이나 비정상 유입을 조사하는 신호입니다.
- 기존 30종 제한과 등록부 1,024행 한도는 서로 다른 범위입니다. 한도를 피하려고 과거 행을 삭제하지 않습니다.

## 배포와 장애

- 현재 Production/Preview URL·배포 ID·커밋, 최근 검증 결과, DB 마이그레이션 상태, 이전 롤백 대상을 기록합니다. 실행 절차는 [배포 문서](deployment.md)를 연결합니다.
- 백업 파일의 실제 위치·복원 검증 여부, 보유기간 정리와 오류 관찰 방법은 [기존 운영 가이드](../operations.md)를 확인합니다. 오래된 환경 가정을 재확인합니다.
- 장애 시각(KST), 영향 화면·QR·캠페인, 개인정보를 제거한 오류, 대응·복구·추가 조치 담당 역할을 남깁니다.

## 다음 담당자에게 남길 미결 사항

- 현장 세부 설치 위치·실제 설치일·점검 주기와 담당 역할.
- 실제 휴대전화 스캔 여부, 최신 OAuth/가입·집계 검증 여부.
- v1.0의 Production 반영 여부. 이번 변경은 Preview 검증까지만 수행합니다.
- 향후 게시판 장소 승인과 신규 캠페인 등록, 용량 검토 일정.
