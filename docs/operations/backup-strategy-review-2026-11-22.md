# 장기 백업 구조 재검토 (2026-11-22)

> **대체됨(같은 날)**: 운영자가 약 18개월간 부재할 수 있어, 사용자가 GitHub Actions + Cloudflare R2(C안)로 결정했다. [cloud-backup-2026-11-22.md](cloud-backup-2026-11-22.md)

- 상태: 조사·설계만 했다. 실제 변경은 없다.
- [오프사이트 설계(R2 + GitHub Actions)](backup-offsite-design-2026-11-21.md)는 **보류**한다.
- 원칙
  - 새 외부 서비스를 들이지 않는 방안을 우선한다.
  - 기존 백업은 중단하거나 삭제하지 않는다.
  - Production 설정·권한은 바꾸지 않는다.

## 1. 확인한 사실과 확인 수준

| 항목 | 값 | 근거 |
|---|---|---|
| Production 요금제 | **Free**(서울, Nano), 제공 자동 백업 없음, PITR 없음 | 2026-10-17 사용자가 대시보드에서 확인한 기록([PRIVACY_RELEASE_REVIEW.md](../PRIVACY_RELEASE_REVIEW.md)). 이후 변경 여부는 **재확인 필요** |
| Preview 요금제 | 미확인 | Production과 같은 조직인지도 미확인 |
| Database → Backups 화면 | 직접 확인 불가 | 이 환경에 Supabase 관리 토큰이 없다. 공식 문서상 Free는 자동 백업이 "Not included"라 **비어 있을 가능성이 크지만 추측하지 않는다** |
| Production 용량(11-22) | DB **20MB** / Storage **22MB** | 03:00 cron이 매일 기록하는 `capacity.*` 집계를 읽기 전용으로 조회(`capacity-status.mjs`). 10-15에는 17MB / 13MB |
| 로컬 백업 | 매일 1회, DB 전체 + Storage 사진, 암호화, 매일 실제 복원 검증. 최신 `auto-2026-11-22`(24.9MB, 57개 테이블, 사진 135개) | 백업 로그와 검증 기록 |
| 로컬 백업 폴더 | 34개 파일, 640MB | 디스크 확인 |

**Supabase 공식 문서 확인**(2026-11-22, backups·pricing·PITR·billing 페이지)

- **Free**
  - 자동 백업 "Not included".
  - 공식 권고: Free 프로젝트는 CLI `db dump`로 직접 내보내 외부에 보관하라.
- **Pro**
  - 일일 백업, **7일** 보존. Team은 14일, Enterprise는 최대 30일.
  - 복원은 **같은 프로젝트를 덮어쓰는 방식**이다. 복원 중에는 프로젝트에 접속할 수 없다(DB 크기에 비례한 중단).
  - 일일 백업을 직접 내려받는 기능은 문서에 없다.
- **백업에 포함되지 않는 것**
  - Storage 파일. 백업에는 `storage.objects` 메타데이터만 들어 있다. "백업 이후 삭제한 객체는 복원되지 않는다."
  - 사용자 정의 역할의 비밀번호.
- **PITR**: Pro 이상 추가 기능. 7일에 약 $100/월(14일 약 $200, 28일 약 $400). 최악 RPO 2분이고, 켜면 일일 백업은 중단된다.
- **프로젝트를 삭제하면 백업도 함께 영구 삭제된다**("including any backups ... irreversible").
- **비용**
  - Pro $25/월(조직 단위). Micro 컴퓨트 1개 분량($10) 크레딧 포함. 프로젝트마다 컴퓨트가 따로 청구된다.
  - 디스크 8GB, Storage 100GB.
  - 유료 플랜은 비활성 일시정지가 없다.
  - Free 한도: 활성 프로젝트 2개, 1주 비활성 시 일시정지, DB 500MB, Storage 1GB.
- 확인하지 못한 것
  - 'Restore to a new project'(프로젝트 복제)가 가능한 플랜
  - 일시정지 시 백업 처리
  - Auth 사용자와 확장 기능의 복원 범위

## 2. 질문별 답

1. **요금제와 백업 기능**
   - Production은 Free(10-17 기준)로, 관리형 백업도 PITR도 없다.
   - Preview는 미확인이다.
2. **Backups 화면에 실제 백업이 있는지**: 미확인. 사용자 확인 항목 U-2.
3. **주기·보존·범위**
   - Free: 없음.
   - Pro로 바꾸면 매일 1회, 7일 보존, DB만 같은 프로젝트에 복원된다.
4. **관리형 백업으로 복원되지 않는 것**
   - **Storage 사진 파일**: 게시글 사진, 비공개 채팅 사진, 신고 증거
   - 사용자 정의 역할 비밀번호. MJU Find에는 `mju_chat_realtime` 등 앱 역할이 있어 복원 후 재설정·확인이 필요하다.
   - 프로젝트 삭제 후의 모든 것
   - Vercel 환경 변수와 비밀값
5. **로컬 백업과 겹치는 부분**: DB 전체 덤프(같은 범위)뿐이다.
   - 로컬 백업에만 있는 것: Storage 사진, 매일 실제 복원 검증, 프로젝트·계정과 분리된 사본, 무기한 보관
   - Supabase 백업에만 있는 것: PC와 무관한 실행, 사용자 조작 없이 같은 프로젝트에 바로 복원
6. **Pro 전환 시 실제 월 비용**

   | 구성 | 월 비용 |
   |---|---|
   | Production만 Pro 조직(Micro 1개) | **$25**(크레딧이 Micro 상쇄) |
   | Preview도 같은 조직에 있음 | $25 + $10 + $10 − $10 = **$35** |
   | 위 + PITR 7일 | +$100(비권장) |

   - 현재 용량(20MB / 22MB)으로는 초과 요금이 없다.
   - Preview가 같은 조직에 있는지는 U-1에서 확인해야 한다. Preview를 Free 조직에 따로 두면 $25로 유지된다.
7. **Free를 유지하면서 높이는 방법**: §4 A안
8. **대응 가능 범위**: §3 표
9. **프로젝트 삭제·계정 탈취·사진 삭제 때 복구 범위**: §3 표

## 3. 장애·침해 상황별 복구 범위

| 상황 | 로컬 백업만(현재) | + Supabase Pro 일일 백업 |
|---|---|---|
| 잘못된 마이그레이션·대량 삭제(DB) | 마지막 로컬 백업 시점까지 복원(실효 1~2일 손실) | **최대 24시간 손실**로 같은 프로젝트 복원(중단 발생). 로컬은 보조 |
| 사진 삭제(Storage) | 마지막 로컬 백업에 있던 사진 복원. 이후 사진은 손실 | **차이 없음**(Storage 미포함) |
| Supabase 프로젝트 삭제 | 로컬 백업으로 새 프로젝트에 DB + 사진 복원 | **차이 없음**(백업도 함께 삭제) |
| Supabase 계정 탈취 | 로컬 백업은 안전. 공격자는 데이터 열람·삭제 가능 | 공격자가 백업 복원·프로젝트 삭제 가능. 실질적 보호는 로컬뿐 |
| 운영 PC 고장·분실·랜섬웨어 | **백업 전부 손실**(PC가 유일한 사본) | DB 7일분은 Supabase에 남음. 사진은 손실 위험(Supabase 원본만 남음) |
| PC가 덮개 닫힘·꺼짐(11-22 사례) | 그날 백업 누락 | DB는 매일 확보 |
| DB 비밀번호 유출로 변조 | 변조 전 로컬 백업으로 복원(변조 탐지 수단은 없음) | 7일 안에서 시점 선택 가능 |

정리하면 다음과 같다.
- Supabase 백업은 **PC가 멈추는 문제**와 **DB 실수**를 보완한다.
- **사진, 프로젝트 삭제, 계정 탈취에는 도움이 되지 않는다.** 이 세 가지는 Supabase 밖의 사본, 즉 지금의 로컬 백업만 막는다.
- 로컬 백업의 가장 큰 약점은 **PC 한 대가 유일한 사본**이라는 점이다.

## 4. 세 안 비교

**A. 기존 로컬 백업 개선**(Free 유지, 새 서비스 없음)

- A-1 **PC가 깨어 있게**
  - AC 연결 시 '덮개를 닫으면: 아무것도 안 함'(Windows 전원 설정). 사용자 설정이며 승인 대상이다.
  - 로그온 후 10분 시점과 놓친 작업 실행은 이미 있다. 감시 작업(26시간)이 경고한다.
- A-2 **두 번째 사본**: 검증된 암호문을 외장 USB 디스크에 주 1회 복사하고 PC와 떨어진 곳에 보관한다. 새 서비스가 아니다.
  - 선택: 이미 쓰는 개인 클라우드 동기화 폴더(예: OneDrive)에 **암호문만** 두는 방법도 있다. 이는 기존 서비스 활용이지만, 국외 보관·위탁 여부 검토가 필요하다.
- A-3 **비대칭 암호화(age)**: PC에는 공개키만 두고 개인키는 오프라인에 둔다. PC가 탈취돼도 과거 백업은 열리지 않는다([hardening §5-2](security-hardening-2026-11-22.md)).
- A-4 **보관 정책**
  - 현재: 일일 7개 + 배포 전 백업 무기한.
  - 제안: 일일 7개 + 주간 4개 + 월간 6개.
  - 배포 전 백업은 6개월 뒤 검토한다. 삭제는 별도 승인을 받는다.
- A-5 **복구 훈련**: 분기 1회, 백업을 새 Free 프로젝트(또는 로컬)에 실제로 복원해 RTO를 잰다.

**B. Supabase Pro 일일 백업 + 기존 로컬 백업**(A-1~A-5 포함 권장)

- 월 $25(Preview가 같은 조직이면 $35).
- Production은 일시정지가 없어진다.
- DB 백업 7일이 PC와 무관하게 확보된다.
- 복원은 대시보드에서 클릭으로 끝나지만, 같은 프로젝트를 덮어쓰고 중단이 생긴다.

**C. 별도 오프사이트(R2 + GitHub Actions)**: 보류. PC 없이 DB와 사진 모두 매일 받을 수 있지만, 계정·토큰·암호화 키 관리가 새로 생긴다.

| 기준 | A. 로컬 개선 | B. Pro + 로컬(A 포함) | C. 오프사이트 |
|---|---|---|---|
| 백업 안정성(실행 보장) | 중. PC 전원에 의존, USB 사본으로 손실 위험 완화 | **상**(DB는 매일 보장, 사진은 A 수준) | 상(PC 무관) |
| 개인정보 보호 | 상(암호문만, 개인키 오프라인, 외부 위탁 없음) | 상(Supabase는 이미 위탁처라 새 위탁 없음) | 중상(새 위탁처, 토큰 관리) |
| 복원 가능성 | DB + 사진 전부(백업 시점 기준), 프로젝트 삭제·계정 탈취에도 복원 | + DB를 하루 이내로, 빠르게 | DB + 사진, PC 분실에도 복원 |
| 비용 | 0원(외장 디스크 1개 정도) | **$25~35/월** | 수 달러/월 이하 |
| 관리 편의 | 주 1회 USB 복사, 분기 훈련 | A와 같음 + 대시보드 확인 | 초기 구축·키 관리 부담 큼 |
| 새 외부 서비스 | 없음 | 없음(기존 업체 플랜 변경) | 있음(Cloudflare, Actions) |

## 5. 추천

**지금은 A를 적용하고, B는 비용 판단 후 선택한다. C는 보류한다.**

- 현재 규모(DB 20MB, 사진 22MB)에서 가장 큰 공백은 'PC가 꺼져 있으면 백업이 없음'과 '사본이 PC 하나뿐'이다. A-1과 A-2만으로 비용 없이 대부분 해소된다.
- Pro의 백업은 **사진·프로젝트 삭제·계정 탈취를 막지 못한다.** 따라서 로컬 백업을 대체할 수 없고, 보조 수단일 뿐이다.
- $25/월의 이점: DB 하루 손실 보장, 일시정지 없음, 빠른 복원.
- Pro 전환을 권하는 시점
  - 실사용자가 늘어 하루치 DB 손실을 감당하기 어려울 때
  - 덮개 닫힘 등으로 로컬 백업 누락이 계속될 때
- PITR($100/월~)은 현재 규모에 비해 과하다.

**적용 순서 제안**(각각 승인 후)

1. A-1 전원 설정(사용자)
2. A-2 외장 디스크 복사 스크립트(옵스 worktree, 기존 파일은 그대로 두고 복사만)
3. A-3 비대칭 암호화 전환(새 백업부터 적용, 기존 백업과 기존 암호는 보존)
4. A-4 보관 정책
5. A-5 복구 훈련
6. (선택) Pro 전환

## 6. 사용자 확인 항목

- **U-1** Supabase 조직 구성: Production과 Preview가 같은 조직인지, 각 조직의 현재 플랜(Settings → Billing).
- **U-2** Production·Preview의 Database → Backups 화면에 백업 항목이 있는지, PITR 표시.
- **U-3** Spend Cap 설정(Pro 전환 시 초과 과금 차단 여부).
- **U-4** 외장 디스크 보유 여부와 보관 장소, 노트북 덮개 동작 변경 허용 여부.
- **U-5** BitLocker(장치 암호화) 켜짐 여부.
