# 포스터 제작·인쇄·배부

이 문서는 절차를 정한 것이며 설치 완료를 증명하는 문서가 아닙니다. 현재 16개 QR은 `ready`, 세부 설치 위치·설치일은 미확정입니다.

1. [UTM 표준](utm-standard.md)과 [등록부](qr-registry.csv)의 실제 건물·용도를 확인합니다. 이번 활동은 `poster_2026_11`, 8개 경비실 × `find`/`reg` 두 종류입니다. MCC는 통합 1곳입니다.
2. 관리자 `/admin/utm`에서 등록부 QR을 선택합니다. 생성에는 `promotion.manage`가 필요합니다. CSV의 URL과 화면 URL이 일치하는지 확인합니다. 자유 입력으로 변경했다면 등록부 일치 안내를 다시 확인합니다.
3. PNG 또는 SVG를 내려받습니다. 파일명에는 source·campaign·content가 포함됩니다. 같은 캠페인의 다른 장소 파일을 덮어쓰지 않습니다. QR 주위 흰 여백 4모듈을 자르거나 다른 문구·그림으로 덮지 않습니다.
4. 최종 인쇄 파일에서 QR을 디코딩하여 CSV URL과 대조합니다. 이미지가 보이는지만으로 합격 처리하지 않습니다. 포스터의 검색/등록 안내 문구와 QR 용도가 일치하는지도 확인합니다.
5. Preview에서 링크 경로·쿼리를 시험할 때는 URL의 origin만 Preview로 바꿉니다. 인쇄용 생성 링크는 항상 Production 도메인입니다. 새 기능이 아직 Preview에만 있으면 인쇄물의 실제 운영 적용은 Production 반영 후 검증해야 합니다.
6. Preview에서 검색 QR, 비로그인 등록 QR, Google OAuth·동의·닉네임·필요한 실명 확인 후 복귀를 시험합니다. 첫 유입 UTM 네 값의 비콘 전송, 서버 집계, DB 카운터, 통계 화면을 각각 확인합니다. 새로고침과 같은 세션의 재방문이 중복 유입으로 세어지지 않아야 합니다. 관리자 방문 제외도 별도로 확인합니다.
7. 시험 인쇄물을 실제 휴대전화로 스캔합니다. 휴대전화 스캔을 하지 않았다면 미검증으로 기록합니다. QR의 인쇄 크기·거리·조명에 대한 고정 합격 수치를 검증 없이 정하지 않습니다.
8. 현장 배부 시 경비실 안의 구체적 위치와 실제 설치일을 확인한 후 `notes`, `installed_on`, `status=installed`를 기록합니다. MCC 층·상업시설을 별도 건물 코드로 늘리지 않습니다. 설치 사실을 확인하지 못하면 `ready`를 유지합니다.
9. 점검 시 실제 QR과 등록부를 대조하고 `last_checked_on`을 기록합니다. 점검 주기와 담당 업무 역할은 운영 인수인계 시 정합니다. 아직 정하지 않은 주기를 기존 운영 사실처럼 채우지 않습니다.
10. 회수·훼손·잘못된 설치는 `retired`와 사유를 기록합니다. 같은 식별자를 다른 장소에 재배정하거나 과거 행·통계를 삭제하지 않습니다.

발급·설치·점검 기록 변경 후 스냅샷 재생성과 `npm run operations:validate`를 실행하고 diff를 검토합니다. 등록부에는 담당자의 실명·전화번호·학생 정보나 비밀값을 기록하지 않습니다.
