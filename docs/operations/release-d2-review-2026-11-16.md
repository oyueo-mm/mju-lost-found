## D-2 변경 범위

별도 fix/release-d2-embedding-control 브랜치. Production은 D-1 cb3bb71 유지, Production DB 쓰기·마이그레이션·서비스 배포 없음. D-2는 이미지 임베딩 재계산/대표 사진 변경의 작업 통제를 구현한다. 텍스트/이미지 모델·전처리·벡터 차원·검색 점수는 바꾸지 않았다.

- ImageEmbeddingJob 테이블과 LostPost/FoundPost BEFORE 트리거. image_url 변경과 같은 트랜잭션에서 작업 등록·generation 갱신·이전 이미지 벡터 null 처리를 한다. 앱이 저장 직후 종료돼도 작업 등록이 빠지지 않는다. 글 삭제 시 작업도 같은 트리거로 정리한다. 기존 행 전체 backfill/추론은 하지 않는다.
- 입력 키는 immutable 이미지 URL과 기존 SigLIP 고정 revision의 SHA-256. 완료된 동일 입력은 저장된 벡터를 재사용한다. 다른 URL로 같은 바이트를 다시 업로드하거나 다른 글의 벡터를 공유하는 전역 캐시는 아니다.
- 공유 DB lease 150초, 모델 실행 함수 maxDuration 120초. 원자적 claim, 같은 글 활성 작업 합류, 만료 후 회수. 저장 시 원본 URL·generation·token·lease 유효성을 잠금 안에서 재검증한다. A→B, 제거, ABA, 늦게 돌아온 worker가 최신 벡터를 덮어쓰지 못한다.
- 벡터 저장·추천 캐시 삭제·작업 완료는 같은 짧은 트랜잭션이다. 추론 동안 DB 행 잠금을 유지하지 않는다. 기존 트랜잭션 밖의 뒤늦은 null 저장은 제거해 새 벡터가 다시 지워지는 경쟁도 막았다.
- 실패 상태와 10초 재시도 시각을 남기고 자동 재시도는 최대 5회. 명시적 소유자 재시도도 cooldown/예산을 지킨다. 변경된 새 입력은 이전 실패의 attempts를 물려받지 않는다. 정상 worker는 최신 pending을 최대 3회 이어서 처리한다.
- after()만 영속 큐로 취급하지 않는다. 일반 검색 GET 응답 후 due 작업 1개를 복구하고, 인증된 embedding-maintenance 모드는 최대 8개를 처리한다. 추가 일간 cron은 기존 /api/posts 함수로 직접 들어오며 신규 모델 함수를 만들지 않는다. Preview에서는 수동 인증 호출로 검증하고 Production 활성화는 이후 배포 승인 범위다.
- 이미지 첨부/대표 사진 변경은 after()에서 내부 함수를 호출한다. 요청 origin/Host/전달 헤더 기반 URL과 Cookie 전달 HTTP 호출을 제거했다. Preview 실배포 번들 검증을 통과하여 직접 호출 방식을 채택했다.
- PUT은 기존 인증·정지·소유권 검사를 유지하고 embedded에 더해 jobStatus를 반환한다. 모델 실패는 503, 예산 초과는 429, 예산 시스템 장애는 503. 진행 중인 작업을 새 성공 추론으로 보고하지 않는다.

## 남은 운영 한계

- 프로세스 장애와 lease 만료 시 물리적 exactly-once 추론까지 보장하지 않는다. 유효 lease 하나와 조건부 저장을 보장하고 함수 실행 상한보다 lease를 길게 두어 겹침을 줄인다.
- 일간 복구와 요청 후 복구는 즉시 실행 SLA가 아니다. 서비스가 완전히 유휴 상태이면 예약 복구까지 기다릴 수 있고, 5회 실패는 명시적 재시도가 필요하다. 대기 작업은 DB에 남아 사라지지 않는다.
- 트리거가 사진 교체 직후 오래된 이미지 벡터를 무효화하므로 새 추론까지는 기존 텍스트 신호로 검색/추천한다. 오래된 벡터를 최신 이미지의 벡터로 제공하지 않는다.
- 앱 롤백 시 새 테이블/트리거를 임의 삭제하지 않는다. 구버전 worker가 fencing을 모르는 mixed-version 위험은 Production 배포 전 별도 확인해야 한다. Production 마이그레이션·배포는 승인 전 금지다.
- 모델 포함량과 검색 응답 시간은 아래에 기록했다. 전체 압축 함수 용량과 운영 p95는 측정하지 않았다. 큰 함수 플래그/요금제/Deployment Protection은 변경하지 않았다.

### 운영 경계

일반 웹/API 이미지 변경·재계산 경로는 공통 제어를 사용한다. 구형 ai-eval-seed 운영 도구는 기존 직접 벡터 저장 helper를 사용하므로 D-2 검증과 병행 실행하지 않았다. 옛 배포/도구의 동시 실행과 롤백 시 fencing 미적용 문제는 Production 전환 전에 별도 차단·종료 절차를 확정해야 한다. 기존 시드 데이터는 수정하지 않았다. 추가 일간 복구는 즉시 완료 SLA가 아니며 생산 환경 고부하 동작은 공격 테스트로 검증하지 않았다.
