### 실제 TLS 사용 확인

배포된 함수의 소켓을 직접 볼 수는 없으므로, 다음 네 가지를 이어서 증명했다.

1. **Supabase 주소만 허용**: Production 런타임은 `accessPolicy.mjs`가 Supabase Production 주소만 허용한다. 다른 주소면 앱이 시작되지 않는다.
2. **TLS 설정이 반드시 붙음**: Supabase 주소에는 `pgPoolSettings`가 항상 `ssl: { ca: Supabase Root 2021, rejectUnauthorized: true }`를 붙인다. URL의 `sslmode` 같은 파라미터는 제거한다.
3. **어댑터가 설정을 그대로 씀**: 앱이 쓰는 `PrismaPg`는 이 설정으로 `pg.Pool`을 만든다. `scripts/operations/db-tls-adapter-check.mjs`로 확인했다.
   - 다른 CA를 넣으면 `TlsConnectionError`로 거부된다. 평문으로 다시 시도하지 않는다.
   - 앱 설정으로는 연결된다.
4. **조회 성공 = 검증된 TLS 연결**: 배포 후 DB를 조회하는 요청이 성공했다. 1~3에 따라 이 연결은 검증된 TLS 연결이다.

| Prisma 마이그레이션 CLI | 미검증 TLS(prefer) | `sslmode=require` + 고정 CA + `sslaccept=strict` (`prisma7.config.ts`) | 동작 |
| 노트북 예약 백업(ops 작업 트리, `ops/backup`) | 스냅샷 평문 + 덤프 미검증 | 검증된 TLS(`0ff6a70`). Preview 실행 성공 | 동작 |

| 롤백(`vercel rollback`) | DB 연결 없음 | 같음 | 단, 대상 배포가 TLS여야 함(5절) |
