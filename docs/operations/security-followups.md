# 별도 보안 개선 추적

## SEC-CDN-DELETE-001: 삭제된 공개 이미지의 CDN 캐시 잔존

- 등록: 2026-11-16, D-1 회귀 검사 중 확인.
- 관측: 사용자 삭제 API 성공 및 인증된 Storage 목록에서 원본 부재·게시글 DB 행 부재를 확인해도, 삭제 전 조회했던 공개 이미지 URL이 200을 반환했다.
- 영향: URL을 이미 알고 있는 사용자가 캐시 만료 전 이미지를 계속 조회할 수 있다. 원본 Storage 삭제 성공과 CDN/브라우저/Next 변환 캐시의 회수는 별개다. 보존 시간은 이번 검증에서 측정하지 않아 단정하지 않는다.
- D-1 처리: 기존 폭·TTL 31일·Preview 비최적화 정책을 유지했다. 신고 증거 버킷은 비공개이며 이 문제의 공개 URL 대상과 구분한다. 캐시 삭제 개선을 D-1 또는 D-2에 섞지 않는다.
- 후속 조사: Supabase 원본 CDN·Next 최적화 CDN·브라우저별 Cache-Control/Age와 응답을 별도 식별하고 삭제/교체/백업 복원 후 전파 시간을 측정한다. Vercel purge 성공 범위와 재시도, Storage 제공 purge 기능, TTL·비용·개인정보 영향, private 전환 시 UI/서명/백업 호환성을 비교한다.
- 완료 기준: Preview 전용 사진으로 삭제 전 각 캐시를 준비하고 원본 삭제 후 계층별 접근 차단 시간을 기록한다. 임의 query cache-busting으로 성공을 주장하지 않는다. 즉시 회수가 불가능한 캐시는 보존 상한과 사용자 고지를 명시한다.
- 상태: 미구현. D-5 고아 파일 정리와도 별개인 캐시 회수 보안 개선으로 추적한다. 실제 Production 데이터로 삭제/공격 실험을 하지 않는다.

## SEC-BACKUP-SNAPSHOT-001: 덤프와 행 수 기록의 snapshot 불일치

- 등록: 2026-11-16. 오늘 04:00 자동 백업이 04:01:45에 복원 검증 실패(작업 결과 1).
- 관측: ActivityDay 96/95, AdminVisit 215/214, ApiMetricHourly 668/667(기록/복원), 51개 테이블 중 3개 불일치. 이미지 134개 누락 0. 오늘 백업을 restore-verified로 인정하지 않는다. 11월 15일 검증된 암호화 백업은 보존.
- 유력 원인: ops/backup@059ce7a의 `scripts/backup/backup.mjs`에서 두 pg_dump 후 별도 연결로 행 수 조회. 같은 export snapshot을 공유하지 않아 동시 운영 쓰기와 시점 차이가 날 수 있다. READ ONLY만으로 덤프와 같은 시점을 보장하지 않는다.
- 향후 개선안(이번에 미구현): 짧은 REPEATABLE READ READ ONLY snapshot export 연결을 유지하고 full/public dump의 --snapshot과 행 수/마이그레이션 목록을 같은 snapshot에 맞춘다. Storage는 외부 시스템이므로 별도 일관성·참조 검증 한계를 다룬다. 스냅샷 유지 시간/DB 부담, 실패 시 연결 정리, 기존 승인 가드·암호화·보존·실제 복원 검사를 보존해야 한다.
- 금지: 불일치 비교 삭제/완화, 검증 표식 강제 생성, 최신 실패 파일로 기존 검증 백업 대체, 사용자 데이터 쓰기 중단으로 문제를 숨기기.
- 완료 기준: Preview 운영 쓰기와 동시에 백업해 동일 snapshot의 행 수가 실제 복원과 일치함을 재현하고, 별도 승인된 Production 읽기 전용 백업의 암호화·체크섬·실제 복원까지 통과한다.
- 상태: **2026-11-16 별도 사용자 승인으로 복구 검증 완료.** 0007e21의 공유 snapshot 수정, ops/backup 반영, Production 읽기 전용 백업 1회 암호화·실제 복원 통과. 실패 파일과 기존 정상 백업 보존. [복구 결과](backup-snapshot-repair-2026-11-16.md). D-1 배포 당시 금지 조건으로 보류했던 기록과 이번 복구를 구분한다.
